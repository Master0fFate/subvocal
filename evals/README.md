# Evals

Subvocal makes three claims, and each one is measured here instead of assumed:

1. **Fewer thinking tokens.** Compared against no instruction (baseline). The
   shipped `subvocal` text is the plain "keep your internal reasoning concise"
   sentence, which beat 13 other candidates, including every notation-based
   one, in the development run (`snapshots/hard-haiku-dev.jsonl`).
2. **Same accuracy.** Every task prompt has one checkable final answer.
3. **Reply unchanged.** Reply length on tasks and on open requests, notation
   leaking into the reply, and whether a Croatian question still gets a
   Croatian answer while subvocal thinks in English.

## Arms

| Arm | System prompt addition |
|---|---|
| `baseline` | none |
| `subvocal` | `skills/subvocal/SKILL.md` body, exactly as the hooks inject it: "Keep your internal reasoning concise: a minimum draft per step, a few words each. Your reply is unaffected: write it as you normally would." |
| `ultrasubvocal` | `skills/ultrasubvocal/SKILL.md` body, exactly as the hooks inject it: "Keep your internal reasoning very concise: a minimum draft per step, a few words each. Your reply is unaffected: write it as you normally would." |
| `plain` / `control` | "Keep your internal reasoning concise. Your reply is unaffected: write it as you normally would.", the 0.1 default; `control` is its name in the oldest snapshots, `plain` in the v2 ones |
| `lite` | the arm name in v0.1 snapshots; not runnable any more |

The arm text is produced by calling the hook code, so the eval tests what ships.

## Prompt sets

- `prompts/hard.jsonl`: 24 multi-step tasks (code tracing, lattice paths,
  logic grids, modular arithmetic, Dijkstra, Game of Life, a stack machine),
  each ending with `Final answer: <x>`. Haiku 5.5 thinks for roughly 300 to
  7000 tokens on each, which is the regime a thinking-style instruction can
  move. Answers were computed by a script, not recalled.
- `prompts/tasks.jsonl`: 18 short tasks (arithmetic, logic, code tracing,
  dates, combinatorics, probability). Haiku thinks about 150 tokens on each,
  so this set mostly measures accuracy and instruction overhead.
- `prompts/open.jsonl`: 6 open requests, one in Croatian.

## Running

```bash
python3 evals/run.py --model haiku --sets hard,open --runs 3 --arms baseline,subvocal --out evals/snapshots/hard-haiku-5-5.jsonl
python3 evals/report.py evals/snapshots/hard-haiku-5-5.jsonl
python3 evals/chart.py evals/snapshots/hard-haiku-5-5.jsonl --out docs/benchmark-haiku.svg
```

`--sets` names prompt files under `prompts/`. `--arm-file name=path` adds an
arm whose system-prompt addition is the text of `path`, which is how candidate
instructions were compared before one was shipped as `subvocal`. `chart.py` draws a
snapshot as a dependency-free SVG, so the chart in the README can be
regenerated by anyone who re-runs the eval.

`--backend claude-cli` (default) uses a logged-in `claude` CLI, which reports
thinking tokens directly. Every call runs from an empty directory with
project-only settings, no tools, no MCP servers, no slash commands and a fixed
system prompt, so nothing installed on the machine reaches any arm.
`--backend anthropic` uses the Messages API (`ANTHROPIC_API_KEY`) and derives
thinking tokens as output minus the counted reply.

Results append one JSON line per call; an interrupted run resumes. Refusals
(`stop_reason: refusal`) are recorded and reported per arm.

## Reading the numbers

- Thinking is adaptive: on easy prompts a model may not think at all. Totals
  only include prompts where at least one arm thought, and the report says how
  many that was.
- Thinking length varies a lot between runs of the same prompt. Use at least
  two runs, and treat differences under ~15% as noise.
- The thinking text itself is not returned by these hosts, so the eval
  measures cost and outcome, not whether the trace literally follows the
  dialect.
